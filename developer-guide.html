Numerical correctness and energy conservation

Performance changes must preserve the intended discrete numerical method. Identify the exact energy diagnostic, field and particle conventions, boundary terms, and expected numerical tolerance from project documentation or validation tests.

  • Track total energy and its component terms using the project’s defined convention.
  • Test changes to particle advancement, deposition, interpolation, and field updates independently where possible.
  • Account for floating-point precision, non-associative reductions, and ordering differences across backends.
  • Separate expected round-off differences from systematic drift or regressions using repeated and controlled tests.
  • Do not claim exact conservation or bitwise CPU/GPU equivalence unless evidence supports it.

Coding standards and contribution workflow

Adapt naming, formatting, branching, commit, and review conventions to any existing project policy. Until that policy is inspected, the following is a proposed generic workflow.

Issue

Describe the bug, scientific motivation, or feature request and define acceptance criteria.

Development branch

Create a focused branch following the repository’s verified naming convention.

Implementation

Make a small, documented change and explain numerical or performance implications.

Testing

Run the relevant tests and record numerical diagnostics or benchmark evidence.

Code review

Provide a clear summary, test results, known limitations, and documentation updates.

Merge

Follow the project's review and integration requirements.
