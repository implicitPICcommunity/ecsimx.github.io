GPU acceleration of ECsim

An OpenACC port offloads moment gathering and the particle mover to NVIDIA GPUs while keeping the MPI structure, with a CUDA implementation in development.

Overview

The GPU port of ECsim is implemented with OpenACC, chosen over OpenMP offloading because it appeared more mature and better supported by compilers at the time, and because it preserves the original code structure. Work is offloaded where the cost is: moment gathering and the particle mover. A pure CUDA implementation is under development; no CUDA results are published here.

Data layout and kernel design

  • Flattened arrays: 3D field pointers were flattened to 1D arrays for locality. Hatted currents are Ns×Nx×Ny×Nz arrays; mass-matrix components are 14×Nx×Ny×Nz arrays with no species index.
  • Scalars instead of small arrays: the 3×3 rotation matrix became nine scalars; the 2×2×2 weight and magnetic-field arrays were flattened.
  • Unrolling: inner interpolation and deposition loops were unrolled by hand. Full unrolling of the mass-matrix loops was avoided because it raised register pressure.
  • Loop order: in the mass-matrix kernel, the neighbour index N′ is the outermost loop and a switch selects one of the 14 stored neighbours.

Race handling: atomics

Many particles deposit onto the same grid node, so accumulation into the current and mass matrices uses #pragma acc atomic update; the diagnostic routines do the same. A sorting-plus-reduction alternative was tried and dropped because of compiler limitations with array-based reductions.

Memory management

The first version relied on compiler-managed transfers with no explicit data clauses; Nsight Systems showed heavy host–device transfers and page faults. The final version uses CUDA managed memory with cudaMemPrefetchAsync to move arrays to the GPU before use and back afterwards, which avoids deep-copying complex data structures. The paper also reports benefits from the unified memory architecture of the GH200.

Toolchain used in the study

The published results used NVIDIA HPC SDK 23.11 (CUDA 12.3, -O3, target cc80 with managed memory), Open MPI 4.1.6, HDF5 1.14.3, PETSc 3.20.1, OpenBLAS and H5hut 2.0.0, with CMake for builds. Validation (1D and 2D two-stream and current-filamentation instabilities) showed CPU and GPU curves overlapping.

Limitations and next steps

  • Only partial offload: the field solver and initialisation remain CPU-bound.
  • I/O, especially raw particle dumps (about 50 s each, three per run in the benchmark), leaves the GPU idle.
  • Strong-scaling efficiency drops beyond 64 GPUs on the smallest tested grid.
  • Large particle counts are needed, and ECsim does not use spatial smoothing.
  • Planned: a CUDA implementation, I/O optimization, better CPU–GPU overlap, and offloading more routines.
