Installation

The OpenACC study built ECsim-X with CMake and the following stack. Treat these as the tested reference configuration, not minimum requirements.

MPIOpen MPI 4.1.6

Repository details needed. Exact CMake options, directory layout, and the supported CPU-only build are not specified here. Take them from the official distribution.

Choosing numerical parameters

  • θ: use θ = ½ for exact discrete energy conservation and second-order accuracy. θ > ½ damps high-frequency waves but gives up exact conservation. θ does not affect stability.
  • Time step and cell size: ECsim is unconditionally stable, so they can be chosen to resolve the physics of interest. In the whistler study it stayed accurate at CFL > 1 (Δt up to 2 ωp-1).
  • Particles per cell: plan for at least about 100 per cell to control noise; ECsim has no spatial smoothing.
  • Solver tolerance: the GMRES tolerance bounds how closely energy is conserved. The ECsim performance study used 10-12.

Running a simulation

# Placeholder only: replace with the verified ECsim-X command
mpirun -np <N> <ECsim-X executable> <input file>

In the published GPU runs, each MPI task is bound to one GPU (four tasks per Leonardo Booster node). The CPU reference used one task per core.

Output and diagnostics

Fields and particles are written with HDF5. Raw particle dumps are slow (about 50 s each in the benchmark) and leave the GPU idle, so dump them sparingly. Track kinetic, electric, and magnetic energy to monitor conservation. Define the energy convention you use, and compare runs with the same solver tolerance.

Troubleshooting

  • Check compiler, MPI, and PETSc versions against the reference stack.
  • For slow GPU runs, profile with Nsight Systems and look for host–device transfers and page faults; the managed-memory prefetch path was introduced to remove them.
  • For energy drift, tighten the GMRES tolerance and confirm θ = ½.
  • For numerical differences between CPU and GPU, compare diagnostics rather than bits; atomic accumulation changes summation order.
  • Record the full error output, build flags, and source revision when reporting an issue.

Frequently asked questions

Which GPUs are supported?

The published results use NVIDIA GPUs: A100 on Leonardo (build target cc80), with V100, H100 and GH200 also compared. Other vendors are not documented.

Does the GPU version change the physics?

The paper reports that CPU and GPU results overlap for two-stream and current-filamentation validation runs.
