Reproducible benchmark protocol

  1. Record source revision, build type, compiler, flags, dependencies, and precision.
  2. Record hardware model, device count, CPU topology, memory, and interconnect.
  3. Specify mesh dimensions, particle count, physical parameters, and output frequency.
  4. Separate warm-up, initialization, timestep, I/O, and total runtime where relevant.
  5. Repeat measurements and report a defined statistic and variability.
  6. Verify numerical diagnostics for every configuration being compared.

Data integration

Suggested future schema: each measurement should include a case identifier, revision, timestamp, backend, hardware, resource count, problem size, precision, runtime, memory use, and validation status. Plotting should be connected to actual structured data only after the schema and units are agreed upon.
